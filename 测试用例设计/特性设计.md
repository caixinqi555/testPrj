
## 背景
目前统计信息在数据变更达10%时触发自动收集，在变更小于10%时新增数据无法被及时统计；由于基数估算模型默认所有数据均被直方图/MCV统计，如果未统计的新增数据在统计信息覆盖范围外，则查询该新增数据范围的谓词结果行数会被错估为1行，导致严重低估行数并导致错选nestloop、选择错误索引等性能劣化/慢sql问题。 误差谓词具体有两类： 
a) 统计信息未覆盖的范围谓词。常见于日期、序列号等递增列，例如：使用时间列范围谓词查询当天的新增数据，如当天新增数据未触发auto_analyze则错估为1行。当前GaussDB/Postgresql的解决方案是简单对直方图选择率以0.0001为下界，但无法解决大多数问题；
b) 统计信息未覆盖的eq谓词。常见于版本号、月份/日期、batch_id等低NDV（<=100）的列，这类列统计信息全为MCV，对于非MCV的值估行为1。
 典型场景如：版本号更新后，业务运行一段时间，查询最新版本号的数据估行为1行。 此类问题在sqlserver社区有较多讨论，一般称为递增列问题The Ascending Key Problem link。SQLServer、Oracle与Oceanbase等友商对该问题均有相应设计，可在上述典型场景解决问题。
本特性针对存在未统计增量数据、同时谓词查询范围不在统计信息范围内，导致基数估算将行数估为1行的场景，根据实时增量行数和现有统计信息给出估行矫正。

配套测试建议统一使用 `analyzed_tuples=10000`、增量 `2000` 行的 fixture；由于该增量已超过 10%，自测/转测时需关闭 autovacuum/autoanalyze，避免统计信息被自动刷新后影响场景复现。
正式 SQL 用例建议统一通过 `\i 测试用例设计/check_erows.sql` 加载 `check_erows` 存储过程，并以 `CALL check_erows(case_id, sql, expected_rows, tolerance)` 的形式固化断言。

## 实现思路 
参考SQLServer方案，在range谓词、var_eq_const两个场景的基数估算函数中进行判断，当且仅当谓词范围完全不在统计信息边界内（现有的静态统计信息估行给出0行估值），触发边界外估行逻辑，使用统计信息数据平均密度*谓词范围大小进行估算，并取实时增量行数作为上界： a) range谓词边界外估行：Min{边界外谓词范围 * （已统计行数 / 统计信息范围），实时增量行数} b) equal谓词边界外估行：Min{1 * （已统计行数 / 已统计NDV），实时增量行数}

## 实现设计

### 矫正方案
统计信息边界为{stats_min，stats_max}，通过直方图和MCV获取；统计信息行数analyzed_tuples通过pg_class获取；实时增量行数increase_tuples通过pg_stat获取（下述）。

#### 一、range谓词
实现位置：clauselist_selectivity函数
示例：select * from t where col > qual_l and col < qual_h；
触发条件：qual_l > stats_max或qual_h < stats_min（仅谓词范围与统计信息完全不重合时触发）
谓词范围部分超出统计信息范围时即触发 
1、计算单位value范围的行密度 density = analyzed_tuples / (stats_max - stats_min); 
2、计算谓词在统计信息边界外的范围 out_of_bounds_width = qual_h – qual_l; 
3、估算谓词在统计信息边界外的行数 out_of_bounds_rows = out_of_bounds_width * density; 
4、边界外行数以“实时未统计行数”作为上界 out_of_bounds_rows = Min(increase_tuples, out_of_bounds_rows); 

优选，仅行数估为0时触发，不影响一般场景
缺点：估行随谓词下界关系不平滑，超过边界时估行会陡增（可接受）
友商方案：Ob的触发条件较宽：只要谓词范围有一部分在统计信息边界外（qual_h > stats_max），即对边界外部分的谓词进行估算。本特性收束影响面，要求谓词范围与统计信息范围不重合（qual_l > stats_max）。

#### 二、gt谓词（where col > qual_l）
实现位置：clause_selectivity函数
示例：select * from t where col > qual_l；
触发条件：qual_l > stats_max
实现与range谓词一致，区别是步骤2的谓词范围上界qual_h不是来自谓词，而是根据统计信息的density外推得到，外推的范围大小根据实时未统计行数占统计信息行数的比例确定：
	qual_h = stats_max + (stats_max – stats_min) * (increase_tuples / analyzed_tuples)

#### 三、equal谓词（where col = qual_c）
实现位置：adt_var_eq_const()
触发条件：qual_c未命中MCV，且other_distinct = 0 (即所有值均为MCV，other_distinct = n_distinct - num_mcv)
对于只有MCV没有otherdistinct的场景，原算法估为0行，修正后按统计数据density给出期望值
1、取行数/NDV作为期望值
target_rows = analyzed_tuples / n_distinct
2、以“实时未统计行数”作为上界
target_rows = Min(increase_tuples, out_of_bounds_rows);

### 实时行数估算方案
1、estiamte_rel_size中记录当前页面数cur_pages、pg_class的页面数stats_pages和行数stats_tuples（旧有函数estiamte_rel_size的实现，对于分区表的主表不会实时估算pages）
2、调用本特性接口时，估算实时增量行数：
2.1 获取cur_pages：(a) 如果未发生分区剪枝/剪枝到多个分区，则采用的是分区表主表的统计信息，则调用现有接口访问下属所有分区的存储层接口获取cur_pages；(b) 如果是普通表或剪枝到单个分区且存在相应分区统计信息的分区表，则直接使用步骤1中记录的cur_pages
2.2 获取统计信息直方图收集时的relpages：尝试访问历史统计信息表，根据当前谓词列访问相应列的最新统计信息的timestamp，然后根据该时间查询对应版本的表级历史统计信息，提取表级历史统计信息的relpages和reltuples。如果因为历史统计信息prune等原因未查询到，则使用estiamte_rel_size中记录的当前relpages和reltuples
2.3 计算增量行数：increase_tuples = (cur_pages - stats_pages) / stats_pages * stats_tuples

## 能力边界与约束
eq谓词支持表达式统计信息和多列统计信息
支持vacuum更新表级统计信息但不更新列级统计信息时增量行数估算不受影响
支持分区表，支持分区剪枝场景

gt和range谓词 不支持谓词列为索引主列的场景（包括表达式统计信息场景）。这是因为该场景直方图边界已修正为实时值，本特性矫正没有额外收益
gt和range谓词 不支持多列统计信息。因为多列统计信息在range谓词场景采用贝叶斯模型估算，工作量过大。
不支持探测pages存在空洞、insert不产生pages增长的场景的增量行数
不支持enable_static_statistics场景

测试执行补充约定：
1、如需清理表 tail 或回收增量场景，不能使用 `DELETE`，应使用 `TRUNCATE` 后重新导数并 `ANALYZE`，避免残留空页面干扰 `increase_tuples`。
2、多列统计信息、表达式统计信息等相关语法以华为云 GaussDB 文档为准：
`https://support.huaweicloud.com/intl/zh-cn/distributed-devg-v8-gaussdb/gaussdb-12-0321.html`
