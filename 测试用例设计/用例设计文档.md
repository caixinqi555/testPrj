
# 边界外谓词估行矫正 — 用例设计

> 对应详细设计：`详细设计.md`（range/gt/equal 谓词在统计信息边界外的估行矫正）
> 测试目标：研发自测/开发转测，聚焦新增代码路径的分支、触发条件、边界值、约束不支持场景的回退
> 断言粒度：分层断言（触发状态 | 估行数 ±容忍 | 公式备注）
> 主开关：`refine_growth_sel`（默认 on）

---

## 0. 特性简述

当谓词范围完全落在统计信息边界外时，原有基数估算给出 0 行（被下界钳制为 1 行），本特性在 range/gt/equal 三类谓词中触发矫正，使用"统计信息数据密度 × 谓词范围"进行估算，并以实时未统计行数 `increase_tuples` 作为上界：

- **range 谓词触发条件**：`qual_l > stats_max` 或 `qual_h < stats_min`
- **gt 谓词触发条件**：`qual_l > stats_max`
- **equal 谓词触发条件**：`qual_c` 未命中 MCV 且 `other_distinct = 0`

## 2. 公共约定

### 2.1 预期注释格式

每条 SQL 前一行（或多行）为预期注释，格式如下：

```
-- 【编号】标签（触发路径 | 表类型 | 统计信息 | 上界状态 | 其它维度）
-- 预期：<触发状态> | estimated rows ≈ <值>（±容忍）| 公式 <min(a, b) = result>
<SQL>
```

**数值容忍**：估行 ±20%（覆盖浮点、页面填充因子、pages 膨胀比例的累计偏差），≤10 行时 ±2 行。

**触发状态** 取值：
- `触发 range 边界外矫正` / `触发 gt 边界外矫正` / `触发 equal 边界外矫正`
- `不触发矫正（原逻辑）` / `不触发矫正（约束回退到原逻辑）`

### 2.2 Fixture 共用约定

每个谓词组（range / gt / equal）开头建一套 **基础 fixture**，组内用例复用，只在需要时追加 insert / vacuum / 切换 GUC。

基础 fixture 统一形态：
- 主测表规模 `analyzed_tuples = 10000`，id 范围 `[1, 10000]`
- ANALYZE 冻结统计信息：`stats_min = 1, stats_max = 10000`
- 测试执行时关闭 autovacuum/autoanalyze，再 `INSERT` 增量数据使 `increase_tuples ≈ 2000`
- 不同表类型（astore/ustore/临时表/分区表）使用相同逻辑结构

### 2.3 让 increase_tuples 可预测

```
increase_tuples = (cur_pages - stats_pages) / stats_pages * stats_tuples
```

`stats_pages` 在 ANALYZE 后冻结，`stats_tuples = 10000`。每页约 226 tuples（8KB 页面、int+timestamp+bigint+varchar ≈ 36 字节），`stats_pages ≈ 45`。

- 目标 `increase_tuples ≈ 2000`：插入 ~2000 行，约增加 8~10 页
- 目标 `increase_tuples = 0`：ANALYZE 后不 insert
- 目标 `increase_tuples` 远大于公式值（验证上界截断）：插入 ~5000 行；若测试环境开启自动收集，需先关闭 autovacuum/autoanalyze

**重置/清理 fixture 的方式**：
- 用例之间需要还原表数据时，**用 `TRUNCATE` + 重新 `INSERT` + `ANALYZE`**，**不要用 `DELETE`**。
- 原因：`DELETE` 不会回收页面，只把元组打死标记；`relpages` 保持膨胀状态，`cur_pages - stats_pages` 不再准确，会污染后续用例的 `increase_tuples`。
- 例外：`R-C-04 / G-C-04 / E-C-02` 的"页面空洞"用例 *主动* 用 `DELETE` 制造空洞，是用例语义本身需要，不属于此处的清理。

### 2.4 断言执行方式

```sql
\i 测试用例设计/check_erows.sql

CALL check_erows('<用例编号>', $$SELECT ...$$, <expected_rows>, <tolerance>);
```

- 正式 SQL 用例优先使用 `check_erows` 存储过程做断言，直接比较顶层 `Plan Rows` 与预期值。
- 容忍度沿用本文约定：常规场景 `0.20`，`expected_rows <= 10` 时由过程内部按 `±2 行` 放宽。
- 仅验证计划形态、分区剪枝路径、回退分支是否命中的场景，可保留 `EXPLAIN` 作为辅助观察。
- 本文后续示例中，能明确从《特性设计》公式推导 `expected_rows` 的，已直接改写为 `CALL check_erows(...)`；仍以路径观察为主的场景暂保留 `EXPLAIN`。

推荐写法示例：

```sql
-- 【R-A-01】触发 range 边界外矫正，预期 rows ≈ 100
CALL check_erows(
  'R-A-01',
  $$SELECT * FROM t_r_astore WHERE id > 11000 AND id < 11100$$,
  100,
  0.20
);

-- 【E-A-01】触发 equal 边界外矫正，预期 rows ≈ 200
CALL check_erows(
  'E-A-01',
  $$SELECT * FROM t_e_astore WHERE ver = 51$$,
  200,
  0.20
);
```

`expected_rows` 推导规则统一来自《特性设计》中的估行公式：

- `range` 触发场景：`expected_rows = min((qual_h - qual_l) * analyzed_tuples / (stats_max - stats_min), increase_tuples)`
- `gt` 触发场景：先按 `qual_h = stats_max + (stats_max - stats_min) * (increase_tuples / analyzed_tuples)` 外推上界，再用 `expected_rows = min((qual_h - qual_l) * density, increase_tuples)`
- `equal` 触发场景：`expected_rows = min(analyzed_tuples / n_distinct, increase_tuples)`
- `increase_tuples = 0` 场景：公式结果为 `0`，最终按原逻辑下界钳制为 `1`
- `refine_growth_sel = off` 或能力边界回退场景：按原逻辑推导；能稳定算出精确值的改为 `check_erows`，仍以路径观察为主的暂保留 `EXPLAIN`

**不触发场景的 pages 膨胀修正**（重要）：
- 在非分区表上，新增 20% 增量行后，`estimate_rel_size` 会按 `cur_pages / stats_pages` 比例膨胀 `reltuples`，原 PG 估行逻辑使用的是膨胀后的 `reltuples ≈ 12000` 而非冻结的 `analyzed_tuples = 10000`。
- 因此**非分区表 + 非触发**用例的 `expected_rows` 需在原直方图选择率的基础上 × 1.2。例如选择率 10% 的 range 谓词：原本 `1000` → 应改为 `1200`。
- 分区表的子分区/主表估行路径不直接走 pages 膨胀，B 组若涉及分区表，按分区路径单独估算，不无脑乘 1.2。
- 触发场景不需要乘 1.2，因为公式直接基于 `analyzed_tuples` 与实时 `increase_tuples`，已包含增量信息。

**分区剪枝 + 触发条件的差一约束**：
- 触发条件是 `qual_l > stats_max`（严格大于），写 `qual_l = stats_max` 不会触发。
- 分区边界 `VALUES LESS THAN (X)` 是开区间，分区上界为 `X-1`。例如 `p11 LT 11001` 含 `id ∈ [10001, 11000]`。
- 设计"剪枝到单分区 + 触发"用例时，谓词需同时满足 `qual_l > 主表 stats_max` 且 `[qual_l, qual_h]` 严格落在某一分区开区间内，避免 `qual_l = stats_max` 或 `qual_l = 分区边界` 的差一误判。
- 若分区在 ANALYZE 之前没有数据，剪枝到该分区时分区无本地直方图，会回退到主表统计路径，公式照常成立。
