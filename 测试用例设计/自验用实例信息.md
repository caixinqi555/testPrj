## 启停

```bash
# 启
pg_ctl -D "$PGDATA" -l "$PGDATA/startup.log" start

# 查状态
pg_isready -h localhost -p 5432
pg_ctl -D "$PGDATA" status

# 停
pg_ctl -D "$PGDATA" -m fast stop
```

## 估行断言存储过程 check_erows

已安装在 postgres 库。源文件：`测试用例设计/check_erows.sql`

签名：
```sql
CALL check_erows(
    p_case_id  text,     -- 用例编号，如 'R-A-01'
    p_sql      text,     -- 被测 SELECT 语句（整体作字符串）
    p_expected numeric,  -- 预期 E-rows
    p_tol      numeric DEFAULT 0.05   -- 相对误差容忍，默认 5%
);
```

输出单行 NOTICE：
```
NOTICE:  [R-A-01] E_rows=101 expected=100 err=1.00% OK
NOTICE:  [R-A-02] E_rows=101 expected=500 err=79.80% FAIL
```

容忍规则：
- 若 `|actual - expected| ≤ 2` 且 `expected ≤ 10` → 判 OK（小值噪声容忍）
- 否则按相对误差 `|actual - expected| / expected` 与 `p_tol` 比较

筛失败：
```bash
psql -d postgres -p 5432 -f 用例.sql 2>&1 | grep FAIL
```

## 注意

- 本 PG 未编译 libxml 支持，`check_erows` 使用 `EXPLAIN (FORMAT JSON)` 提取顶层 Plan Rows
- autovacuum 默认是全局配置，灌测试数据时建议 per-session `SET` 关闭，避免干扰 `increase_tuples`
- 本实例是研发编译版，不是 GaussDB；用例设计目标是 GaussDB，本地只用于调通 check_erows 以及需要回归到 PG 原逻辑的对比验证
